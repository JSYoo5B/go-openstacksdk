See the [support ledger](../docs/sdk-support-ledger.md) for status definitions and shared limitations.

Python/Go differences:

- Go replaces ambiguous Python name_or_id strings with explicit resource.Ref. IDs use only an initial member GET; Names use exact Collection resolution and then a fresh fixed-ID confirmation GET. Python Resource.find first tries member GET and can fall back after400/403/404 to a detail list matching ID or name. The extra Go confirmation shifts initial absence after a name-list race: Go can returnfalse where Python would ignore a later mutation404 and returntrue.
- Go branches on the selected Cinder Microversion, with strict canonical3.<minor> validation and3.23 as the threshold, rather than Python utils.supports_microversion endpoint/default support discovery. Connection may discover a configured latest/range before helper capture; direct helper does no discovery or fallback. Empty Type is normalized on the copied client for consistent native version headers.
- Go normal DELETE always includes canonical lowercase cascade=false and selected modern force=true/false. Legacy Force sends pinned Python os-force_delete:null rather than native Gophercloud empty string. Go admits only the documented/native finite mutation status sets plus clean404, preserves opaque responses and rejects arbitrary route/query/body/session controls; existing native leaves retain independent behavior.
- Both helpers default to waiting forever after deletion rather than proxy standalone120s. Go nil/numeric-zero Timeout is unlimited and negative/inactive-invalid policy is rejected before HTTP. Python iterate_timeout treats numeric-zero/negative wait as immediate post-mutation timeout before the first deletion fetch. Positive Go context deadlines interrupt HTTP/timers while Python checks elapsed time between fetches; caller context additionally controls lookup and mutation.
- Go fresh200 observations require matching safe canonical IDs and strict known nullable types. Missing/null/empty status continues with no failure predicate; pinned Resource.wait_for_delete invokes resource.status.lower() when the Resource has status and may fail forNone. Python falsy fetch and mutable cached Resource behavior are represented by explicit Go404/deleted proof rather than arbitrary object truthiness or seeded hydration.
- Python returns one bool or raises. Go exposes Found/Deleted plus independently owned Located/Deletion/LastAccepted/Absent/Ready evidence even after accepted processing errors. Waitfalse Deletedtrue denotes completed request handling, not an observed absence. GET404 is independent absence evidence; mutation404 is retained only as Deletion proof. Error-returning callback0, raw nullable models and local option preparation are explicit Go extensions.
- Go only treats a clean direct logical Name miss or clean admitted physical404 as absence/race. Nested transport/native/list/read/Close/context/source failures remain errors with original causes. Captured client settings and fixed request ownership preserve current native authentication/retry without claiming packet-level exactly-once, arbitrary provider mutation, cleanup or rollback.
- This candidate maps only the direct cloud delete_volume declaration under its documented Go policies after implementation and meaningful QA. Separately inventoried Python find_volume/delete_volume/wait_for_delete and inherited Resource/session/cache/API-version behavior keep independent reviews. Cinder v3 selection does not assert full Cinder v2 Resource semantics or whole-SDK completion.

Examples use the surrounding guide's service object and context unless they declare a complete program. Python examples describe the pinned comparison API.

import openstack

conn = openstack.connect()
