Python/Go differences:

- The pinned public add_ips_to_server returns mutable Server Resource and dispatches pool > truthy ips > auto/needs. Independent typed Service/Connection AddIPsToServer now provides bounded Neutron and legacy Nova selected modes with async/whole60second defaults and structured Decision/Attempts/Server/Observed plus separate Neutron Assignment or NovaAssignment. Existing Plan/Ensure/ready/create keep their distinct default/readiness policies; Nova Plan is diagnostic and independent execution replans.
- Disabled/private/AccessIPv4/floating/empty skips apply to automatic mode only. Pool/list requests bypass automatic needs, and only the final winning selector is validated; pool does not inspect ignored address strings. Empty list/zero pool clears selection. Concrete IPv4/Ref inputs, owned snapshots and option preparation replace Python dynamic coercion; full Resource/session/normalization and has_service configuration/version behavior remain partial.
- Unlike the source needs helper swallowing some floating-network SDKException as false, only a clean completed semantic plan absence becomes a skip. HTTP/decode/read/Close/source/cancellation/ambiguous or other explicit-selector failures remain errors. Strict destination tuple selection, revision protection and re-GET behavior follow the separately reviewed Go Neutron plan.
- Existing stronger Ensure, synchronous GetActive, Wait and creation require matching actual ACTIVE server and exact assigned version4 floating-tagged raw row. Independent WithServerIPWait instead observes that exact row under any server status and does not wait for Neutron ACTIVE; supplemental/AccessIPv4/fixed/IPv6 metadata cannot prove raw observation in either family. Both retain known resources without automatic cleanup/backend fallback; per-item observations do not prove simultaneous final presence.
- Independent AddIPsToServer defaults to one60-second overall context, async and five-second raw poll, with explicit helper wait/timeout overrides. Existing Ensure/automatic creation retain five-minute/two-second synchronous defaults; GetActive/Wait retain their180second/five-second and readiness policies. Go also bounds selection/HTTP work and shares one budget across items, whereas source forwards timeout60 into wait branches and repeated list attachments. The address lane performs Python's attached-IP refresh; the pool and automatic lanes do not (see remaining).
- The selected Neutron pool lane reuses Ensure and may prefer already-attached candidates or allocate attached directly. Bounded Nova pool mode instead selects raw instance_id=null in the literal pool or allocates by POST200, compatibility GET and separate action202; it retains actual pre-action association fields. Sequential Observed records item-time targets, not simultaneous final presence.
- Direct Nova/None explicit or precise absent-Network selected execution requires actual legacy Compute capability. Missing Compute, selected microversion>=2.36 and unsupported Neutron port/NAT/project overrides remain typed capability failures. In the pool and automatic lanes a Neutron failure does not fall back to Nova (see remaining). Nova has no IP status and receives no synthetic ACTIVE. Token sharing and accepted action proof are preserved separately from observation.
- AddIPFromPool takes the pool as a typed name or ID Ref, whereas Python matches one string against both the name and ID of external floating networks. Its already-attached check looks for the exact floating address among the server's addresses rather than comparing only Python's first public floating address.
- The address selector runs Python's add_ip_list branch through the same steps as positional AddIPList: the supplied model's single floating IPv4 short-circuits an item (ShortCircuited, never observed), an associated IP on a model without floating IPv4 refreshes the server once, the NAT destination port is chosen as in _nat_destination_port, and a clean Neutron 404 from the port listing or association PUT after selection is recorded in AttachmentNotFound with the item left incomplete and the call continuing. With wait the raw observation still runs and succeeds when the address appears, or ends with DeadlineExceeded before the next lookup. A 404 from the address lookup itself is not swallowed: it fails the item and stops the list.
  Tests: `compute/server_ip_source_attach_test.go:TestSourceIPListNeutronNotFoundFallsThroughAfterSelection`.
- Raw-wait polling calls WithAutomaticIPProgress with owned copies of each unconverged raw Server (raw-1, raw-2) and returns the third converged model; a progress error stops after one raw GET with the item incomplete and no second lookup. With a fixed-address selector and a refresh of an associated second IP, every request of both items shares one deadline: default about 60 seconds, an earlier 30-second parent, or the parent deadline when unlimited.
  Tests: `compute/server_ip_source_attach_test.go:TestSourceIPListRawPollProgressAndDeadlines`.
- The legacy Nova address lane applies the same supplied-model short circuit after its unfiltered inventory list: the first address short-circuits with no selected-ID GET or addFloatingIp, while the second sends the action with the requested fixed address and observes only in wait mode. Nova rows carry no port, so no refresh runs, and Nova action errors are never swallowed.
  Tests: `compute/server_ip_source_attach_test.go:TestSourceIPListNovaShortCircuitSkipsRecheckAndAction`.

Python/Go differences:

- Network Attach remains one-existing-IP Neutron foundation with safe IDs/IPv4 names and stable association movement. Typed ordered consumers and independent positional AddIPList now execute Neutron or bounded legacy Nova lists. Positional order/duplicates/empty no-op and async whole60second defaults remain; results contain structured Server/Attempts plus separate Neutron Assignment or NovaAssignment rather than mutable Python Resource or dynamic str/list coercion.
- The Neutron Attach path consumes all address pages, locally matches exact addresses and pins opaque destination/revision/port invariants. The Nova consumer instead reads unfiltered legacy inventory, validates only the selected candidate, rechecks its ID/address/pool/association and sends addFloatingIp; it has no Neutron port/revision. Both reject ambiguity and late inventory failures before execution; current fixtures do not prove every pagination shape.
- Network Attach remains async with an optional common five-minute/two-second Neutron ACTIVE waiter. Independent AddIPList defaults to async/60second whole context/five-second raw poll; WithServerIPWait observes each exact raw IPv4 without requiring server/IP ACTIVE. Existing Ensure/sync ready/create consumers keep stronger ACTIVE checks. Each Observed attempt is historical, not simultaneous final presence of all targets. Source list passes timeout60 independently to each attach; Go uses one shared operation context and preserves partial evidence without cleanup.
- Bounded Nova execution retains actual allocation/pre-action fields and accepted200 allocation or202 empty-action evidence in additive NovaAssignment, without synthesizing IP ACTIVE or overwriting instance_id after action acceptance. Strong workflows still require actual raw server ACTIVE/target convergence; standalone wait observes the exact target under any status. Version<2.36 and no Neutron-only port/NAT/project overrides are deliberate capability restrictions. Python's Nova attach lists the inventory again to find the selected ID; Go rechecks it with one singular GET and skips the action when that recheck already shows the server and requested fixed address (AlreadyAttached), where Python would post addFloatingIp again.
- Only the standalone AddIPList/AddIPsToServer address lane evaluates the source short circuit, conditional refresh, NAT-destination port choice and NotFound fall-through. Python's get_server_ip(public=True) probes TCP reachability when several floating addresses exist; Go opens no probes and treats several floating IPv4 addresses as no short circuit, so the normal path decides (it skips the PUT only when the Neutron association already matches the chosen tuple). A supplied Server without address metadata, which Python cannot evaluate, also takes the normal path. A short-circuited item reports ShortCircuited and is never observed.
- Python logs a Neutron NotFound during attachment and returns as if attached. Go records the native 404 in the attempt's AttachmentNotFound, leaves Completed false and returns nil error unless the optional observation fails; cancellation, source changes and validation errors are never swallowed. The Neutron lane additionally rechecks the chosen port and IP and sends If-Match with the original revision before the PUT, which Python does not do.
- WithEnsurePort is a Go-only destination selector; with it the strict PrepareAttach destination policy applies instead of _nat_destination_port.
- Results are immutable owned snapshots rather than Python's mutable Resource with adapter, session, cache and dirty state (SDK-R1/C1/S1); see Deliberate runtime differences in docs/sdk-support-ledger.md.
- Inputs are typed Go values; arbitrary Python objects, iterables and numeric types accepted by dynamic kwargs have no equivalent; see Deliberate runtime differences in docs/sdk-support-ledger.md.
- Lookup errors while polling return immediately with their cause, following the Gophercloud WaitFor convention; Python's cloud wait_for_server ignores every exception and keeps polling until its timeout. Retries for transient HTTP failures belong to the ProviderClient retry settings; see Deliberate runtime differences in docs/sdk-support-ledger.md.
- Evidence is local HTTP fixtures and pinned-source comparison; authenticated deployment acceptance is a separate evidence class shared by every operation (see docs/sdk-support-ledger.md).

## Usage examples

Examples use the surrounding guide's service object and context unless they declare a complete program. Python examples describe the pinned comparison API.

```python
import openstack

conn = openstack.connect(cloud="dev")
server = conn.get_server("web-01")
if server is None:
    raise RuntimeError("server not found")

# standalone defaults: timeout=60, wait=False, auto_ip=True, reuse=True
added = conn.add_ips_to_server(server, ip_pool="public", auto_ip=False)
added = conn.add_ip_list(server, ["198.51.100.10", "198.51.100.11"], wait=True)
```

```go
package main

import (
    "context"
    "flag"
    "fmt"
    "os"
    "strings"
    "time"

    sdk "github.com/JSYoo5B/go-openstacksdk"
    "github.com/JSYoo5B/go-openstacksdk/compute"
    "github.com/JSYoo5B/go-openstacksdk/resource"
)

func main() {
    cloud := flag.String("cloud", "dev", "clouds.yaml entry")
    id := flag.String("server-id", "", "existing Nova server ID")
    mode := flag.String("mode", "dispatch", "dispatch or list")
    pool := flag.String("pool", "", "exact external network name")
    ips := flag.String("ips", "", "comma-separated existing IPv4 addresses")
    wait := flag.Bool("wait", false, "observe each address in raw Nova")
    flag.Parse()
    ctx, cancel := context.WithTimeout(context.Background(), 3*time.Minute)
    defer cancel()
    if err := run(ctx, *cloud, *id, *mode, *pool, *ips, *wait); err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(1)
    }
}

func run(ctx context.Context, cloud, id, mode, pool, ips string, wait bool) error {
    if id == "" || (mode != "dispatch" && mode != "list") {
        return fmt.Errorf("provide -server-id and -mode dispatch or list")
    }
    conn, err := sdk.Connect(ctx, sdk.WithCloud(cloud))
    if err != nil {
        return err
    }
    service, err := conn.Compute(ctx)
    if err != nil {
        return err
    }
    server, err := service.Servers.Get(ctx, id)
    if err != nil {
        return err
    }
    if server == nil || server.ID != id {
        return fmt.Errorf("Nova returned a different or missing server")
    }
    var addresses []string
    if ips != "" {
        addresses = strings.Split(ips, ",")
        for i := range addresses {
            addresses[i] = strings.TrimSpace(addresses[i])
        }
    }
    var automatic []compute.AutomaticFloatingIPOption
    if len(addresses) != 0 {
        automatic = append(automatic, compute.WithFloatingIPAddresses(addresses...))
    }
    if pool != "" {
        automatic = append(automatic, compute.WithFloatingIPPool(resource.Name(pool)))
    }
    options := []compute.ServerIPOption{
        compute.WithServerIPAutomaticOptions(automatic...),
        compute.WithServerIPWait(wait),
    }
    var result *compute.AutomaticServerIPResult
    if mode == "list" {
        result, err = conn.AddIPList(ctx, server, addresses, options...)
    } else {
        result, err = conn.AddIPsToServer(ctx,
            compute.AutomaticFloatingIPRequest{Server: server}, options...)
    }
    if result != nil {
        fmt.Printf("mode=%s observed=%t\n", result.Mode, result.Observed)
        if result.Assignment != nil && result.Assignment.FloatingIP != nil {
            ip := result.Assignment.FloatingIP
            fmt.Printf("ip=%s address=%s status=%s\n", ip.ID, ip.FloatingIP, ip.Status)
        }
        for _, attempt := range result.Attempts {
            // ShortCircuited: the server already showed this address.
            // AttachmentNotFound: Neutron returned 404 after selection and
            // the item continued, so no association is confirmed.
            fmt.Printf("step=%d requested=%s completed=%t short=%t observed=%t notfound=%v error=%v\n",
                attempt.Index, attempt.RequestedAddress, attempt.Completed,
                attempt.ShortCircuited, attempt.Observed,
                attempt.AttachmentNotFound, attempt.Error)
        }
    }
    return err
}
```
