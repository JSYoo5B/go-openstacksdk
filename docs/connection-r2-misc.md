# Connection-level helpers

These helpers correspond to Python `Connection`/`OpenStackCloud` methods. They live in the root package.

## Global request ID: `Connection.GlobalRequest`

`GlobalRequest(id)` returns a new `Connection` that shares the authenticated provider (token, HTTP client, reauthentication) and sends `X-OpenStack-Request-Id: id` on every request made through services obtained from it (built-in services and `CustomServiceClient`). The receiver and services already obtained from it are unchanged. The ID is fixed for the life of the derived connection: Go has no in-place `set_global_request_id`, so concurrent requests can never observe a change. Derived connections need no `Close`. The ID must be non-empty printable ASCII without spaces; the `req-` prefix honored by services is not enforced. The header is not added to Keystone token requests.

## Endpoint lookup: `EndpointFor`, `SessionEndpoint`, `HasService`

`EndpointFor(type, ...)` returns `(url, found, error)` from a `WithEndpoint` override of that type, else the recorded token catalog (first matching endpoint in catalog order, interface and region as in keystoneauth `url_for`). Region and interface default to the connection's and can be overridden per call with `WithEndpointRegion` and `WithEndpointInterface`; `WithEndpointServiceName` filters on the catalog name. No request is made. Without a recorded token result the provider's endpoint locator is used; without either, `ErrNoAuthResult` is returned. `SessionEndpoint` uses the same lookup and rejects version bounds.

`SessionEndpointContext(ctx, type, ...)` maps `get_session_endpoint` with `WithEndpointMinVersion` and `WithEndpointMaxVersion` (keystoneauth notation such as `2`, `v2.1`, `3.latest`, `latest`). An override is returned without discovery. With bounds, the catalog endpoint is selected as above and keystoneauth's discovery runs within the context:

- A catalog URL whose path version lies within the bounds and has the maximum's major version is returned without a request.
- Otherwise version documents are fetched without a token (a 401 is retried once with the current token) from the unversioned URL, the catalog's versioned URL, the identity `/v2.0` hack and the catalog URL, in that order, until one returns a version document (`versions.values`, `versions`, `version`, or a bare version object with microversion headers).
- The newest `CURRENT`, `STABLE`, `SUPPORTED` or `DEPRECATED` version in range is returned as its self link; relative links resolve against the discovery URL and links on another host are repaired onto it. A project ID removed from the catalog URL (the token project, or the segment after a version segment without one) is appended again.
- When the document has no matching version, `found` is false. When no URL returns a document, the catalog URL is returned.
- A minimum without a maximum means `latest`; a maximum without a minimum matches nothing unless it is `latest`. The aliases `volumev2`, `volumev3`, `sharev2` and `workflowv2` imply their major version even without bounds.
- Invalid, contradictory or alias-mismatched versions and malformed version entries are errors (Python raises). Discovery is not cached, and cancellation stops it with an error.

`HasService(type, ...)` and `HasServiceVersion(ctx, type, version, ...)` map `has_service`. Both first consult `ServiceEnabled(type)`: the `has_<type>` flag (type lower-cased with `-` replaced by `_`) from `WithServiceEnabled` or the selected clouds.yaml cloud, else whether the type is an official service type of the os-service-types 1.8.1 data. Aliases such as `volumev3` are therefore disabled unless enabled explicitly; a disabled service is `(false, nil)` without a lookup. `HasService` then performs the catalog lookup without discovery. `HasServiceVersion` with a nonempty version asks `SessionEndpointContext` for that minimum and `<major>.latest` as maximum, as Python does; an empty version means no version. clouds.yaml flags must be booleans and are validated by `Connect`; region-specific values are not read. Not provided: os-service-types alias resolution during catalog lookup and Python's `False` for lookup failures (Go returns the error).

## Re-authentication: `ConnectAs`, `ConnectAsProject`

`ConnectAs(ctx, AsUsername(...), AsProjectName(...), ...)` authenticates again with the options recorded by `Connect` (including values resolved from clouds.yaml) plus typed overrides, and returns an independent connection that inherits endpoint, region, interface, microversion, HTTP/TLS and policy options and the cloud/region location facts. It has its own token, service cache and no global request ID, custom services or shared discovery cache. Python's discard rule is kept: overriding user name or ID discards both, user domain ID/name, and project ID/name. A project selected by name inherits the project domain of the previous name scope, else the user domain, unless `AsProjectDomainID/Name` is given. With a user ID the inherited user domain is dropped because Identity v3 rejects both. `AsAuthOptions` edits the resolved `AuthOptions` directly. `ConnectAsProject(ProjectRef{ID, Name, DomainID})` is the dict form; an ID wins over a name. Connections from `FromProvider` record no credentials and return `ErrNoRecordedAuth`. Authentication happens once per call within the context and is never replayed.

## Custom services: `AddService`, `CustomServiceClient`

`AddService(name, factory [, endpoint])` registers a Gophercloud client factory on one connection (and connections derived with `GlobalRequest` later); built-in names cannot be replaced and registrations cannot change. `CustomServiceClient(ctx, name)` builds the client lazily once and caches it. Python registers on the `Connection` class for the whole process; Go is instance-local.

## Inventory: `Inventory`

`NewInventory`, `NewInventoryFromCloudFiles` and `CloudNames` mirror `OpenStackInventory`. `ListHosts` lists the servers of each cloud in order through the cloud `list_servers` path (`servers.API.ListCloudRecords`, the Python `Proxy.servers` listing described in `compute/v2/servers-list-python.md`): `GET /servers/detail`, following continuation links, with `all_tenants=True` only for `WithInventoryAllProjects`, and each `InventoryHost.Record` keeps the Source row; a cloud contributes nothing if its listing fails. The default aborts at the first failing cloud and returns earlier hosts with the error; `WithInventoryContinueOnCloudError` records failures instead. Cancellation always aborts. `SearchHosts` and `GetHost` apply glob identifier selection and local filters (`WithInventoryFilters`) over `InventoryHostView`; `GetHost` returns nil for no match and `resource.AmbiguousError` for several. Like Python's default `expand=True`, every listed server is expanded into `CloudServerHostvars` (`InventoryHost.Hostvars`, see `compute/cloud-server-composed-python.md`); `WithInventoryExpand(false)` keeps only the interface expansion (`InventoryHost.Interfaces`) and the Go extension `WithInventoryBare()` skips both. `WithInventoryPrivate(true)` maps the `private` constructor flag for that call through `compute.WithPrivateCloud(true)`. Filters then see the expanded keys (for example `public_v4`, `interface_ip` or `flavor.name`). An expansion failure fails that cloud like a listing failure; the security group and volume steps record their failures in the hostvars instead. Python's `use_direct_get` is accepted but unused and `refresh` only invalidates the Python cache, so neither has a Go counterpart.

## Project cleanup: `PlanProjectCleanup` and `ExecuteProjectCleanup`

Python `project_cleanup` deletes resources across services in dependency order with filters, dry run and a status queue. Go splits it into `PlanProjectCleanup`, which only discovers the current token project's resources and returns an inspectable plan, and `ExecuteProjectCleanup`, which deletes exactly that plan's candidates and reports one outcome per candidate. Compute, block storage, network, image, object storage, key manager and orchestration are implemented; load balancer and DNS (phase 2) are reported as not yet supported, and the review stays unresolved until they are. See [projectcleanup/README.md](../projectcleanup/README.md) for options, outcome states, safety rules and coverage.
